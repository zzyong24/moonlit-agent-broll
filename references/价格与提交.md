# 价格与提交

## 月明团队默认：muse2api

本机 muse2api 走 Muse 免费档时，现金金额为 0，但每段占周额度（占用比例与重置周期以使用者账户实际为准，须自行核实）。使用前须在 `providers/muse2api.json` 填写 `api.base_url` 与 `api.quota_account_id`。确认关卡照旧保留。

```sh
M="python3 -B $SKILL_DIR/scripts/muse.py --project $PROJECT --timeout 180"
$M quota                                   # 实时额度（Key 从环境变量 MUSE2API_KEY 读取；如需文件由用户传 --env-file，不打印）
$M estimate --request "$PROJECT/.agent-broll/requests/BR01.json"
$M confirm --quote "$QUOTE_ID" --user-confirmation "$USER_CONFIRMATION"
$M submit --quote "$QUOTE_ID" --job BR01   # 先查额度，≥95% 拒绝；只发一次
$M wait --attempt "$QUOTE_ID--BR01"        # 轮询原任务并下载到 .agent-broll/results/
$M quota-after --attempt "$QUOTE_ID--BR01" # 记录提交后额度
```

请求示例：`{"id":"BR01","anchor":"原句","model":"muse-video","mode":"first_frame","prompt":"…","duration":5,"ratio":"16:9","images":[{"path":"首帧.png","role":"first_frame"}]}`。

以下为原版秘塔 H3 说明，作为备选保留。

## 计价来源

秘塔 H3 的模型能力、计费规则、官方链接和核对日期统一放在 `providers/metaso_h3.json`。本文不另存单价，避免说明与执行各算一套。按本次模式、时长、分辨率、输入素材和附加项使用 `scripts/h3.py` 估价。

本版依据[秘塔 H3 官方产品页及接口面板](https://metaso.cn/minimax-h3)和[秘塔官方接入 README](https://github.com/meta-sota/ComfyUI-MiniMaxH3-API/blob/main/README.md)，核对日期 **2026-10-09**。已整理输出分辨率计费、输入图片超额计费、参考视频计费、音频计费、独立 Context IR 优化项，以及产品页给出的兑换基准；具体规则只读上述 JSON。页面的约合现金价与精确兑换值有差异，按 JSON 保留各自口径，不将约价当精确扣费。

最终积分取整方式、账户实际档位、失败退款规则标“未知”。页面与 README 的最低时长口径不一致，执行器仅接受已交叉支持的范围；争议规格先核实，不默默调整请求。查询窗口有限，按 JSON 记录的官方范围及时保存结果。

每次准备付费提交前重读该接入的来源及未核实项。关键计费规则查不到时不能给出完整报价，不猜金额、不沿用其他平台价格。账户实际档位、积分取整等未核实项须原样展示，能核实先核实；用户若选择按已知基准做最小测试，须明确确认本次报价及这些未知项，Agent 不能代批。付费提示词优化默认关闭，本轮脚本不支持开启 Context IR。

## 默认按批确认，每次提交仍展示

完整故事板通过后，将本批所有镜头逐条列价，列出合计和预算余额，让用户确认一次；用户也可指定逐条确认。每条包括：模型、模式、时长、分辨率、各计费项及其来源、本次金额、剩余预算。金额区分页面展示价相加、兑换基准等值与理论积分；预算余额是本地按报价估算，不能当供应商的实际余额。不要只给总价，也不要只问“预算够不够”。

确认须对应具体请求和报价版本。预算上限、故事板通过、以前说过“可以生成”都不能替代本批报价确认。每次实际提交前再次展示该次金额和剩余预算；未变化且仍在已确认批次内可免重复询问。

重做、改参数、换模型、添加输入素材或开启付费附加项，都重新估价、列价和确认；即使预算尚有余额也不例外。已有任务的查询和下载恢复不产生新生成，不为它另交一条视频任务。

## 提交与恢复规则

1. 没有用户确认过的报价，脚本拒绝提交。
2. 请求发出前先落盘“即将提交”的请求内容和估价；拿到远端任务编号立刻保存。
3. 发送后超时、断网或未收到可靠编号，标“提交结果不明”。能依据原任务查询就查；查不到就停下来告知用户，不能自动重交。
4. 重启看到遗留“即将提交”且无编号，按结果不明处理；本地记录不能证明远端未接单。
5. 已有编号时，查询失败只重试查询，下载失败只重试下载，绝不再次提交。先查看原记录，再继续对应操作。
6. HTTP 200 但响应内容为错误应判失败；下载到空文件或网页错误页也应判失败。下载不携带生成 Key。

## 费用与交付

估价用于确认与预算决策，实际费用以可靠扣费信息为据。拿不到实际费用时写“实际费用未核实”，保留估价及未结清的预留，不把估价当实扣、失败当退款。首次使用新收费组合时，让用户以实际扣费核对计价规则。

交付列明本地结果、原文锚点、请求时长和实际时长、估价与实际费用、检查状态。只抽帧不等于完整审看，没听音频须写明。请求、任务和费用记录在项目 `.agent-broll/`；角色库和模型选择在用户配置目录；Key 不进任何输出或记录。

## 可执行入口

宿主先将 `SKILL_DIR` 指向本 skill 的实际安装目录，将 `PROJECT` 指向用户选择的项目；`BUDGET_CNY` 用用户给定预算，不能替用户填金额。全局参数放在子命令前。以下只示范操作，不构成费用确认：

```sh
python3 -B "$SKILL_DIR/scripts/h3.py" --help

# 先准备请求，再估价；整批可重复 --request，不能只报第一条
python3 -B "$SKILL_DIR/scripts/h3.py" --project "$PROJECT" estimate \
  --request "$PROJECT/.agent-broll/requests/BR01.json" \
  --budget-cny "$BUDGET_CNY"

# QUOTE_ID 是刚返回的 quote_id；确认文字必须来自用户实际消息
python3 -B "$SKILL_DIR/scripts/h3.py" --project "$PROJECT" confirm \
  --quote "$QUOTE_ID" --user-confirmation "$USER_CONFIRMATION"

# 先向用户展示本次金额与剩余预算，再提交这条已确认请求
python3 -B "$SKILL_DIR/scripts/h3.py" --project "$PROJECT" \
  --key-env METASO_API_KEY --timeout 30 submit --quote "$QUOTE_ID" --job BR01

# ATTEMPT_ID 使用记录返回的编号；恢复只能沿此编号查询和下载
python3 -B "$SKILL_DIR/scripts/h3.py" --project "$PROJECT" \
  --key-env METASO_API_KEY query --attempt "$ATTEMPT_ID"
python3 -B "$SKILL_DIR/scripts/h3.py" --project "$PROJECT" \
  --key-env METASO_API_KEY download --attempt "$ATTEMPT_ID"
python3 -B "$SKILL_DIR/scripts/h3.py" --project "$PROJECT" records
```

Key 若在用户已建立的凭据文件，使用全局参数 `--key-file "$KEY_FILE"` 代替 `--key-env`；只给读取位置，不把 Key 值放命令行。脚本不负责写用户配置，不往请求、确认或记录复制 Key。`--test-server` 仅用于本机假服务器测试，不能拿它绕过真实服务的报价确认。

### 请求准备

请求文件放项目 `.agent-broll/requests/`。下面是首帧模式字段结构；原文、提示词和图片路径都替换为本次已批准内容，示例不自带角色或生成授权：

```json
{
  "id": "BR01",
  "anchor": "原稿中本段的准确原句与已有时间锚点",
  "model": "MiniMax-H3",
  "mode": "first_frame",
  "prompt": "本镜头已通过的视频提示词",
  "duration": 5,
  "resolution": "768P",
  "ratio": "adaptive",
  "images": [{"path": "本镜头干净首帧的实际文件路径", "role": "first_frame"}],
  "prompt_optimization": false
}
```

本版 `mode` 可用 `text_to_video`、`first_frame`、`first_last_frame`、`reference`；时长只接受 5–15 秒整数，分辨率只接受 `768P` / `2K`。首帧／首尾帧模式 `ratio` 必须为 `adaptive`，不能混入多参考。其他模式按 provider 中的能力填写，不能默默改用户规格。

`images` / `videos` / `audios` 可省略；每项 `path` 或 `url` 二选一，配相应 `role`：`first_frame`、`last_frame`、`reference_image`、`reference_video`、`reference_audio`。URL 视频须填已核对的 `duration_seconds`；本地视频按实际容器时长计费。远端 URL 或 `mm_file` 的内容版本须用户核对，本地素材批准后发生内容变化会拒绝提交，应重新审改与报价。

重做请求必须加 `redo_of` 指向原尝试编号，另报另确认；“提交结果不明”的原任务不能盲目重投。请求不得包含 Key、账户秘密或代替审批的文字；禁止绕过脚本直接用临时网络命令提交付费任务。

### 本轮边界

脚本按单写者顺序执行，不支持多 Agent 共用预算锁。运行文件仅在项目 `.agent-broll/` 下的 `quotes`、`attempts`、`results`；用户配置由宿主放在用户选择的配置目录。下载保守拒绝重定向，遇到跳转就报告下载未完成，不新生成。

容器检查和 `mvhd` 实际时长不是解码检查、连续观看或听审。查询 `usage` 不是实际扣费证明；本版实际费用保持“未核实”，后续若有可靠账单证据再补，不能用估价覆盖它。
