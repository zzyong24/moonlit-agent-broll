# 图片故事板

## 先出第一格，让用户定风格

从确认的选段中挑一格能代表人物、材质、场景和镜头语言的画面，默认用用户配置的生图脚本（如 dudu / gpt-image-2，`python3 <用户配置的生图脚本> --prompt-file <提示词.txt> --out <项目>/.agent-broll/boards/<镜头>.png --size 1536x1024 --model gpt-image-2 --image <角色参考图>`），备选 Codex 内置生图；角色一致性靠把积木人 `front.png` 作为 `--image` 参考。把所选角色和场景关系写清楚，展示后让用户确认或修改风格。第一格获认可只锁定风格，不能代替整批审阅。

宿主无生图能力时，请用户配置图片模型或手动导入故事板图片，不把文字分镜当作完成了图片关卡。第三方图片模型若收费，生成前独立列价确认。

## 再出整页

每格展示一个明确状态，同时在格外写：

- 原文锚点与该镜头要表达的关系。
- 起始状态、变化、结束状态。
- 出场角色和承担的作用。
- 景别、构图、机位及必要的运动方向。

这些是审阅注记，不是正式画面中的关键词牌。单张图无法完整表示变化时，可用相邻状态说明动作，但别把大量步骤塞进同一格，造成无法判断人物和空间关系。

Agent 自查去字测试与静音测试，写出画面如何成立；不成立的格先改。再交用户逐格审改，确认故事、身份、动作路径和风格一致。整批通过后保存批准版本；未通过的格不提交视频生成。用户修改只处理受影响的格，不默默换掉已通过方案。

## 通过后单独出干净首帧

依据每个通过的故事板格，重新生成该镜头起点的独立画面：无格框、编号、原文、注记或其他镜头，保留批准的人物位置、场景和动作起始状态。检查图像确实适合作为“动作尚未开始”的起点，而非将结束动作提前画完。

这张干净图才是视频请求的首帧参考。**整页故事板网格不能直接上传给视频模型。** 若干净首帧改变了主要关系或风格，先回到用户审改，不把它当作无影响的技术转换。

## 可跳过的唯一情况

用户已给出明确单个镜头和生成参数时，可以不做整页故事板，只补齐影响结果或报价的缺项。多个镜头、整篇口播、只有预算或一句“直接生成”都不能绕过关卡。故事板通过仅批准画面方案，视频消费另行列价确认。
